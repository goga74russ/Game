# Архитектура демо v1 (UE5) — «Грозовые Выси»

> **Решения директора 2026-09-26:** см. `memories/consensus.md` → «Решения по архитектуре демо» (технический тест первым; Скелет не вырезать; только бесплатные ассеты на старте; «почти победил» = финальная фаза + урон в ней).

Объём — только `docs/slice_v1.md`. Правила — `docs/GDD_v1.md` §4–6, 9, 12, 14. Метки: [?] — не уверен, проверить; [Д] — решает директор.

## 1. Решения

| Тема | Решение | Почему / альтернатива |
|---|---|---|
| Движок | UE 5, **последняя стабильная 5.x на момент установки, зафиксировать и не обновлять до конца демо** | Смена минорной версии посреди проекта ломает ассеты/плагины. Лаунчер-сборка, не из исходников |
| Шаблон | Пустой **C++ проект** + Game Animation Sample (GASP) как донор анимаций/локомоции | Blueprint-проект потом переводить в C++ больно |
| C++ vs BP | **Вся логика, состояние, числа — C++** (Claude пишет, видит, компилирует через текст). **BP — только тонкие наследники-«обёртки»**: какой меш, какие анимации, какие звуки/VFX, ссылки на ассеты. Правило: в BP нет веток логики длиннее 3 нод | Claude не видит BP-графы; BP нельзя диффать и ревьюить. BP-логика = код, который никто не может отладить |
| GAS | **Да, но узко**: AttributeSet (HP, Stamina, Yar, Armor, 4 резиста), GameplayEffect для урона/статусов/баффов, GameplayAbility для перекат/ближний/камни/атаки босса, GameplayTags как общий язык состояний | Даёт готовые: модификаторы Increased/More (через кастомный ExecCalc), кулдауны, теги-блокировки, **и репликацию с предсказанием для будущего коопа**. Альтернатива «своя система статов» проще на неделю, но кооп потом = переписать всё. Риск: GAS многословен — Claude его хорошо знает, это приемлемо |
| Ввод | **Enhanced Input**, контексты: `IMC_Spark`, `IMC_Skeleton`, `IMC_Flesh`, `IMC_UI` | Смена стадии = смена контекста ввода, ноль if-ов |
| Камера | `SpringArm` + `UCameraComponent`: фиксированный изометрический ракурс, абсолютное вращение стрелы, масштаб колесом; параметры C++ доступны в категории Camera/Isometric. WASD по осям камеры, курсор задаёт направление героя и цель | По просьбе директора 2026-09-28; изометрический прототип сохраняет существующий бой и этапы героя |
| AI | **StateTree** для мобов и босса | Состояние текстовое/табличное, проще описать директору, лучше дружит с C++-задачами, чем Behavior Tree. BT — запасной вариант, если StateTree окажется сырым в выбранной версии [?] |
| Анимации | Игрок: **локомоция из GASP (Motion Matching)** + монтажи для выстрела/переката/удара. Босс/мобы: **обычный AnimBP + State Machine + Montages**, без Motion Matching | MM для игрока даёт качество бесплатно; для босса нужна детерминированная длина телеграфа — монтаж с AnimNotify точнее. Retarget через IK Retargeter на скелет UE5 Manny |
| Данные | **DataTable (CSV/JSON в репо)** для табличного: оружие, патроны, камни, поддержки, мобы, узлы дерева, атаки босса, реплики. **DataAsset** для ссылок на ассеты (меш, монтаж, звук). Claude правит CSV → директор жмёт Reimport | CSV диффается и читается Claude; баланс без перекомпиляции |

## 2. Модули и классы (один модуль `FadedNav`, папки вместо модулей)

- **Персонаж.** `AFNCharacter` (ASC + AttributeSet), стадия — `EFNStage {Spark, Skeleton, Flesh}` + компонент `UFNStageComponent`: меняет меш/AnimBP, IMC, доступные способности (GrantAbilities по DataAsset стадии), уклонение (телепорт/рывок/перекат). Счётчик убийств → переход (порог в DataTable [Д]). Плоть — базовая; Искра и Скелет = урезанные наборы (slice, этап 4).
- **Оружие/патроны.** `UFNWeaponDef` (DataTable: урон, скорострельность, разброс, отдача, тип патрона, hitscan/projectile), `UFNWeaponComponent` (2 слота + ближний удар). Выстрел — GameplayAbility, трассировка на клиенте сейчас, на сервере потом. Патроны — атрибут по типу, пикап `AFNAmmoPickup` (восковое золото, столб света). Дроп — таблица мобов.
- **Камни и поддержки.** `FFNGemRow` (ранг D–B, стоимость Яри, способность-класс, теги), `FFNSupportRow` (модификаторы-GE + совместимые теги). Камень = GameplayAbility, поддержка = набор GE/тегов, навешиваемых при активации. 3 слота активок.
- **Ярь.** Атрибут `Yar` + GE «копление от нанесённого урона» + малый реген. Ничего особого.
- **Руны и дерево.** `FFNTreeNodeRow` (id, позиция, соседи, требуемая руна, GE-эффект, тип: малый/нотабл/кейстоун) — **дерево ручное, 20–30 узлов, без генератора**. `FFNRuneRow` (id, какие узлы открывает, вес дропа). `UFNTreeComponent`: открытые/вкачанные узлы → Apply GE. UI — UMG `WBP_Tree` с C++-базой `UFNTreeWidget` (рисует узлы по координатам из таблицы; директор только красит).
- **Треба.** `AFNShrine`: чекпоинт (сохранить точку респауна), полное лечение, возврат обычных мобов, открыть экран камней/дерева. Смена камней/рун — только в её радиусе (тег `State.AtShrine`).
- **Мобы.** `AFNEnemy` (ASC, AttributeSet), `FFNEnemyRow` (статы, дроп, StateTree-ассет), 3–5 типов = строки таблицы + разные StateTree/монтажи. Элита = флаг + модификаторы + точка парирования.
- **Босс Перун.** `AFNBossPerun : AFNEnemy`. Фазы — `FFNBossPhaseRow` (порог HP, набор атак, мобы-патроны). Атака — `FFNBossAttackRow` (монтаж, длительность телеграфа, урон, смертельная да/нет, тег звука). **Исход экзамена** — `UFNExamDirector`: считает метрики (мин. HP босса, время, сколько смертельных атак пережил) → решает: «наставник остановил» (с репликой «почти» / «рано») или «победа». Пороги — таблица [Д].
- **Читаемость.** `UFNTelegraphComponent` на боссе: из AnimNotifyState `FNTelegraph` запускает **позу (монтаж) + звук + один импульс** (материал-параметр по силуэту, red-white только здесь). Глобальный `UFNReadabilitySettings` (DataAsset): палитра каналов §12, насыщенность эффектов игрока ≤80%. Debug-команда `fn.GrayscaleCheck` (пост-процесс ч/б) для проверки.
- **Сохранение.** `USaveGame`: стадия, дерево, камни, треба. Смерть — респаун на требе.

## 3. Будущая сетевая граница (не реализуется)

- **Сервер authoritative:** атрибуты (HP/Ярь/патроны), применение урона и GE, смерть, дроп рун/патронов, открытие узлов дерева, стадия персонажа, AI и фазы Перуна, исход экзамена, треба.
- **Клиент предсказывает:** движение, выстрел (визуал + трасса, сервер подтверждает), перекат, активацию способностей (GAS prediction).
- **Только локально:** камера, UI, телеграф-импульс (запускается от реплицируемого монтажа).
- Правила сейчас: вся мутация состояния — через GAS или через функции `Server_`-стиля в одном месте; никакой логики в UI; никаких синглтонов «игрок №0» в геймплее (`GetPlayerCharacter(0)` запрещён вне UI).

## 4. Этап 1 — пайплайн Перуна end-to-end

Шаги:
1. Директор: установить UE, создать C++ проект, добавить GASP, серый уровень-арена. Claude: каркас `AFNCharacter` (ходит/стреляет примитивно), `AFNBossPerun`, `UFNTelegraphComponent`, DataTable атак.
2. Модель: **временный гуманоид на скелете Manny/Quinn** (крупный масштаб, свой материал) — пайплайн проверяется до арта. Финальная модель позже (этап 6).
3. Анимации 3–5 атак (например: удар молотом с замаха, рывок-таран, молния с неба по метке, круговой разряд, бросок) — источники ниже, ретаргет на Manny.
4. Монтажи + AnimNotifyState телеграфа + звук-заглушка + импульс-материал.
5. StateTree: дистанция → выбор атаки из таблицы → кулдауны.
6. Тест: ч/б скриншот, 3 незнакомых человека с видео.

Источники (лицензии проверять на момент скачивания):
| Источник | Коммерчески | Примечание |
|---|---|---|
| Epic-контент (Manny/Quinn, GASP, Paragon-персонажи/анимации) | Да, **только в проектах на UE** | Лучший стартовый вариант |
| Fab, Standard License | Да, в том числе Personal tier | Personal и Professional дают одинаковый объём прав по Fab Standard License; проверять лицензию конкретного ассета и записывать её в реестр. CC BY и другие лицензии учитывать отдельно |
| Mixamo | Да, в игре royalty-free по FAQ Adobe | Нужен Adobe ID; качество атак «тяжёлого» босса проверять на временной модели. Условия использования конкретного ассета сохранить в реестре |
| ИИ-генераторы 3D (Meshy, Tripo, Rodin и т.п.) | Обычно да на платных тарифах, бесплатные — часто CC BY или ограничения [?] | Риг и топология требуют правки; проверять ToS каждого |
| ИИ/видео-мокап (Move.ai, Rokoko Vision и т.п.) | [?] по тарифу | Свои движения директора = свои данные, лучший вариант для уникальных атак |

**Этап пройден, когда:** в сером уровне Перун-заглушка проводит ≥3 атаки по таблице; у смертельной атаки есть поза+звук+импульс; ч/б скриншот различает телеграф; ≥2 из 3 тестеров по видео предсказывают смертельный удар; добавление 4-й атаки = строка в CSV + монтаж, **без правки C++**; 60+ FPS на 4070 Ti (замер `stat unit`, не на глаз).

## 6. Риски и что резать

Риски: (1) анимации босса «деревянные» — главный, поэтому этап 1 первым; (2) директор-не-программист упирается в редактор (ретаргет, монтажи) — нужны очень точные инструкции, время ×2; (3) GAS-бойлерплейт тормозит начало; (4) стрельба «ватная» — это звук/отдача/хит-реакции, не код; (5) лицензия ассета выяснится поздно — вести `docs/tech/assets_licenses.csv` с первого ассета.

Резать первым (по порядку): 5-й и 4-й тип мобов → вторая элита → ранг B камней → Скелет как отдельная стадия (Искра → сразу Плоть) [Д] → дерево до 15 узлов (два выбора сохранить!) → финальный намёк кат-сценой (оставить репликой). **Не резать:** читаемость Перуна, два исхода экзамена, ощущение стрельбы.
